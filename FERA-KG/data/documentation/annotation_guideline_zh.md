# TCFT-EVR 四类关系证据标注指南 v1.1

## 1. 任务范围

每条记录包含一个冻结段落、带类型的 head、关系定义和带类型的 tail。标注者只判断当前冻结段落是否支持给定的 head、关系方向和 tail，不使用外部医学知识、知识图谱路径、模型输出、旧标签或其他标注者的答案。

本任务判断的是历史文本中的证据关系，不判断现代临床有效性、安全性或科学真实性。

## 2. 四类标签与固定判断顺序

必须依次执行以下判断，前一条件成立后不再继续。

1. `ENTITY_OR_TYPE_ERROR`。head或tail存在边界错误、OCR异常、身份错误或类型错误。
2. `INSUFFICIENT_CONTEXT`。两个实体均有效，但冻结段落因截断、指代不明、OCR缺失或上下文不足，不能可靠确认或否定关系。
3. `SUPPORTED`。实体和上下文均有效，文本明确支持给定head、关系方向和tail。
4. `NOT_SUPPORTED`。实体和上下文均有效，但文本未表达该关系，或表达的是并列、相反方向、其他主体、其他对象或其他关系。

“难判断”不是选择 `INSUFFICIENT_CONTEXT` 的充分理由。只有信息本身不足时才能使用该类。

## 3. 九类关系的类型约束

| 关系显示名 | head类型 | tail类型 | 判断重点 |
| --- | --- | --- | --- |
| 食材与历史病症关联 | 食材 | 病症 | 文本是否把治疗或食疗作用归于该食材及该病症 |
| 食材具有传统功效 | 食材 | 功效 | 功效是否明确属于该食材 |
| 食疗方包含食材 | 食疗方 | 食材 | 文本是否明确列出该方所含食材 |
| 历史病症与食疗方关联 | 病症 | 食疗方 | 文本是否把该病症与具体食疗方的治疗联系起来 |
| 食疗方采用烹饪方法 | 食疗方 | 烹饪方法 | 方法是否用于制作该方 |
| 食材与历史禁忌关联 | 食材 | 禁忌 | 禁忌主体是否为该食材 |
| 食材具有食性 | 食材 | 食性 | 寒、热、温、凉等食性是否归于该食材 |
| 食材具有食味 | 食材 | 食味 | 酸、苦、甘、辛、咸等食味是否归于该食材 |
| 食材归入经络 | 食材 | 归经 | 归经对象是否明确属于该食材 |

如果表中类型约束不成立，优先选择 `ENTITY_OR_TYPE_ERROR`，不要继续判断关系。

## 4. 实体边界和类型

以下情况通常属于 `ENTITY_OR_TYPE_ERROR`：

- 实体跨度多截了动作词、结构词或谓词，例如“取羸竹”“胡荽之”“专入肾”。
- 实体跨度包含无关标点、OCR乱码或无法稳定识别的字符。
- 头尾实体把方书名、文献来源、章节标题或目录项当作具体食疗方。
- 将食疗方当作食材，或将食材当作食疗方。
- tail包含关系谓词，而不是纯实体，例如把“专入肾”整体标成归经实体。
- 头尾实体相同，或者tail只是head的别名而非关系对象。

如果人为扰动后的跨度仍恰好构成有效同义名或完整实体，应继续判断关系，不能因为它来自扰动样本就强制判为实体错误。

## 5. 同句共现和关系所有者

head与tail位于同一句中，不代表关系成立。必须确认语法和语义所有者。

- “牡蛎……恶麻黄”中禁忌主体是牡蛎，麻黄是被“恶”的对象，不能建立“麻黄→恶麻黄”。
- “雄燕子一个，酸石榴皮半两”中“酸”修饰石榴皮，不是雄燕子的食味。
- “卖擂茶，或卖盐鼓汤”是两种并列饮品，盐鼓汤不是擂茶的食材。
- 目录中相邻出现的两个菜名、方名或方法只是并列项目，不构成包含或采用关系。
- “甲或乙”“甲、乙分别……”等替代、选择和并列结构不能当作关系证据。
- 文本中的禁忌、功效、食味、归经和病症必须归属于给定head，而不是附近的另一实体。

## 6. 名称、引文和关系证据

- 方名含某个食材字样，不足以证明配方一定包含该食材。若冻结段落只出现名称而无配方，可根据上下文完整程度选择 `INSUFFICIENT_CONTEXT` 或 `NOT_SUPPORTED`。
- 名称中出现“甘”“酸”等字符，不等于文本明确将相应食味归于该实体。
- “《某某方》治……”中的“某某方”可能是方书或来源名称，不一定是具体食疗方。
- 文本说某组合方治疗某病，不能自动把组合中的每个成分单独判为治疗该病，除非关系定义和原文支持这种归属。
- 别名关系、来源关系和并列关系不能替代候选关系。

## 7. `NOT_SUPPORTED` 与 `INSUFFICIENT_CONTEXT`

选择 `NOT_SUPPORTED`：

- 原文完整，实体和指向清楚，但关系属于其他主体或对象。
- 两个实体只是并列、相邻或共同出现。
- 文本明确表达了不同关系或相反方向。
- 目录或列表结构足以确认二者是独立项目。

选择 `INSUFFICIENT_CONTEXT`：

- 关键句被截断，关系所需的前文或后文不在冻结段落中。
- OCR缺失导致主体、宾语或否定词无法判断。
- 代词或省略对象无法从当前段落恢复。
- 多个候选主体同时存在，现有文本不能确定谓词归属。

## 8. 证据与理由填写标准

- `SUPPORTED`：摘录能够同时说明head、关系和tail的最短充分证据。
- `NOT_SUPPORTED`：说明实际主体、实际对象、并列结构、方向错误或关系错误。
- `INSUFFICIENT_CONTEXT`：指出缺少的具体信息，不写笼统的“无法判断”。
- `ENTITY_OR_TYPE_ERROR`：说明是边界、OCR、实体身份还是类型错误，并在可能时给出正确实体形式。
- 共同出现的文本窗口本身不是充分理由。
- 置信度1表示非常不确定，5表示非常确定。

## 9. 盲态与数据完整性

1. 两名主专家独立填写，不讨论单条答案。
2. 不查看生成分层、隐藏抽样目标、模型输出、图路径或旧标签。
3. 不修改ID、冻结段落、实体、类型、关系定义或offset。
4. 第三专家只处理两名主专家的分歧。
5. 所有记录必须包含人员匿名编号和日期。

## 10. 版本说明

v1.1根据首轮300条pilot、84条盲态构念复核和46条独立协调结果定稿。新增内容集中在实体边界、关系所有者、并列共现、方书与食疗方区分，以及名称不能替代关系证据。首轮pilot继续归档，不进入任何locked test。
